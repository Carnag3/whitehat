# Лаборатория аудита информационной безопасности (Hyper-V & OpenVAS/GVM)

Практический стенд для проведения внутреннего аудита защищённости сетевой инфраструктуры, поиска уязвимостей и отработки сценариев тестирования на проникновение (White Hat) в изолированной среде.

## Архитектура стенда

* **Гипервизор:** Microsoft Hyper-V (хост `TECH-LAP03`)
* **Изоляция сети:** Виртуальный коммутатор `LAB-PRIVATE` (тип Private, полная изоляция от внешней сети и интернета, статическая маршрутизация `10.10.20.0/24`)
* **Внешний контур обновлений:** `Default Switch` (NAT) для загрузки сигнатур уязвимостей

| Узел | Роль в инфраструктуре | Сетевые интерфейсы | Инструментарий и ОС |
| :--- | :--- | :--- | :--- |
| **LABBA** | Сервер безопасности и аудита | `eth0`: `10.10.20.10/24` (LAB-PRIVATE) / `eth1`: DHCP (NAT) | Kali Linux, OpenVAS / Greenbone (GVM), Nmap, SSH |
| **metasploit2** | Тестовый уязвимый сервер (Target) | `eth0`: `10.10.20.20/24` (LAB-PRIVATE, Legacy Adapter) | Metasploitable 2 (Linux 2.6.24) |

## Решённые инженерные задачи при развёртывании

1. **Конвертация и адаптация образов VMDK в VHD:** Устранён сбой кодирования StarWind V2V Converter путём прямой конвертации диска через `VBoxManage clonehd` с выносом путей из кириллических директорий.
2. **Совместимость сетевых драйверов ядра Linux 2.6.24:** Заменён синтетический сетевой адаптер Hyper-V на эмулируемый `Legacy Network Adapter` и синхронизирована конфигурация VLAN ID между узлами стенда.
3. **Оптимизация отказоустойчивости Greenbone (GVM / OpenVAS):**
   * Устранён аварийный останов службы `gvmd` (Out-Of-Memory при импорте более 95 000 сигнатур) за счёт выделения и подключения swap-раздела объёмом 4 ГБ (успешно импортировано 191 140 NVT).
   * Настроена ролевая модель и привязка `Feed Import Owner` по UUID администратора для разблокировки профилей сканирования `Full and fast`.
   * Выполнена инициализация базы PostgreSQL, генерация сертификатов и настройка прав доступа для служб `_gvm` и `gsad`.
